# ADR-0035 — Activity Execution Routing

> **Status:** Accepted  
> **Date:** 2026-07-04  
> **Sprint:** SPR-007 — AT-001  
> **Decided by:** Project owner (Sprint 007 authorisation)  
> **Related:** [Document 021](../021-notification-activity-attention-management-framework.md) · [ADR-0032](./ADR-0032-notification-routing-model.md) · [ADR-0029](./ADR-0029-knowledge-discovery-execution-routing.md) · [ADR-0033](./ADR-0033-activity-timeline-framework-package.md)

## Problem

Milestone 7 must define how Platform Events become Activity entries and how Timeline Experiences consume them — without:

1. A parallel execution pipeline
2. Direct Event Bus consumption by UI
3. Activity Mapping routing through Notification Service
4. Modules writing activity records directly

Document 021 and Platform 4.0 establish Event Bus as the shared transport. Notification Mapping already subscribes. Activity Mapping must be an independent sibling.

## Decision

### Architectural principle (locked)

```text
Platform Capability
        ↓
Domain Event
        ↓
Platform Event Bus
        ↓
Activity Mapping
        ↓
Activity Service
        ↓
Activity Presentation Layer
        ↓
Timeline Experiences
```

| Rule                                             | Enforcement                                                          |
| ------------------------------------------------ | -------------------------------------------------------------------- |
| Activity **consumes** events                     | `ActivityMapper` subscribes to Event Bus                             |
| Events are **never** generated by Activity layer | No `publish()` in ATF activity/timeline modules                      |
| Modules **never** write activity directly        | No public `recordActivity()` on capability SDK                       |
| UI **never** imports Event Bus                   | Experiences use `useActivityService()` / `useActivityPresentation()` |
| Activity ≠ Notification                          | Separate mappers, services, stores, Experiences                      |

### Parallel subscribers on Event Bus

```text
                    Event Bus
                   /         \
                  /           \
    NotificationMapper    ActivityMapper
            ↓                      ↓
    NotificationService      ActivityService
            ↓                      ↓
    Notification Experiences   Timeline Experiences
```

**Neither mapper depends on the other.** Same envelope may produce both a notification and an activity item — intentional fan-out at independent layers.

### Event → Activity pipeline

1. **Publisher** — Platform Capability or audit hook publishes validated `PlatformEventEnvelope`
2. **Dispatch** — `InProcessEventBus` synchronously calls subscribers
3. **Activity Mapping** — `DefaultActivityMapper.map(envelope)`:
   - Resolve matching activity types from Activity Registry by `eventPattern`
   - Render title/body templates from envelope payload
   - Produce immutable `ActivityItem`(s)
4. **Activity Service** — `addActivities(items)` appends to session store; notifies subscribers
5. **Presentation** — `mapActivityItemToViewModel()` + timeline grouping
6. **Experience** — Timeline feed / Context panel renders view models

Activity Mapping **never** calls `notificationService.addNotifications()`.

### Activity Experience consumption

Timeline Experiences **must**:

| Requirement          | API                                                                                                                               |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| List activity        | `useActivityPresentation()` → `viewModels`, `groups`                                                                              |
| Subscribe to changes | `useActivityService().subscribe()` (internal to hooks)                                                                            |
| Mark viewed          | `useActivityService().markViewed(activityId)`                                                                                     |
| Navigate / act       | `actionRef` → existing `useCommandRegistry().execute()` ([ADR-0029](./ADR-0029-knowledge-discovery-execution-routing.md) pattern) |

Timeline Experiences **must not**:

- Import `@apzhub/event-notification-framework/server`
- Call `eventBus.subscribe()` or `publish()`
- Import `DefaultActivityMapper` or registry internals
- Write to Notification Service

### Selection and action delegation

When `ActivityItem.metadata.actionRef` is present:

```text
Timeline Experience
        ↓
delegateActivitySelection(actionRef)
        ↓
useCommandRegistry().execute(actionId)
        ↓
DefaultActionExecutor → existing pipeline
```

No new execution gateway. Same constraint as Knowledge selection delegation.

### Wiring in application integration (AT-013)

Production wiring mirrors EN-015 / ENF pattern:

```text
createAppActivityTimelineContext()
  → shared EventBus (from EventNotificationContext)
  → wireAppActivityTimeline({ eventBus, activityMapper, activityService })
```

Test-only wiring helper allowed in AT-007 tests — not used in production path (mirrors EN-014 `wireNotificationMapperToService` test helper).

### Scope boundaries (SPR-007)

| In scope                             | Out of scope              |
| ------------------------------------ | ------------------------- |
| In-process mapper subscriber         | Persistent activity store |
| Session-scoped Activity Service      | Cross-device sync         |
| Personal + workspace timeline scopes | Team timeline RBAC depth  |
| Context panel tab scaffold           | Real-time push updates    |

## Alternatives

| Alternative                                 | Why rejected                                       |
| ------------------------------------------- | -------------------------------------------------- |
| Activity via NotificationService            | Violates separation; wrong read/update semantics   |
| Activity Mapper inside ENF package          | Couples M6/M7; rejected in ADR-0033                |
| Client-side activity recording              | Bypasses Event Bus; inconsistent with Platform 4.0 |
| New execution pipeline for timeline actions | Violates ADR-0029                                  |

## Consequences

- AT-007 implements ActivityMapper + Event Bus subscription
- AT-008 implements ActivityService public API
- AT-010–AT-012 implement Presentation + Experiences
- AT-013 wires app context without modifying ENF package internals (imports EventBus type/instance only)
- Code review checklist includes "no Event Bus in Experience imports"

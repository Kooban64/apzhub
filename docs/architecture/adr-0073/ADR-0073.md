## Context

Platform 1.3 ENG-004 delivered Notification Delivery Phase A under ADR-0071 Option D. Migration **0065** defines Postgres tables for intent, delivery, attempts, and in-app items. Runtime authoritative state remains **process-local Maps** with an in-process interval worker (P13-KL-ND-03). Platform-1.4-ARCH-001 accepted the release theme requiring durable notification runtime as MUST epic P14-E01.

## Problem

Process-local runtime loses queue/retry/DLQ/idempotency state on restart, cannot safely multi-instance claim work, and weakens operational administration — verified against repository evidence.

## Decision drivers / constraints

See [DECISION-DRIVERS.md](./DECISION-DRIVERS.md) · [CONSTRAINTS.md](./CONSTRAINTS.md).

## Options considered

A Postgres-owned · B Postgres+Redis coordination · C Event Bus/Outbox orchestrated · D External broker · E Retain process-local — see [OPTIONS-ANALYSIS.md](./OPTIONS-ANALYSIS.md) · [DECISION-MATRIX.md](./DECISION-MATRIX.md).

## Decision

**Select Option A — PostgreSQL-Owned Durable Runtime.**

1. **Authoritative SoR:** Platform PostgreSQL notification delivery plane (extend **0065**).
2. **Work claiming:** Transaction-safe row leases (`SKIP LOCKED` class) with expiry/reclaim.
3. **State machine:** Existing contract statuses; `processing` means claimed.
4. **Attempts:** Durable try records per dispatch.
5. **Retry / DLQ:** Persist `retry_scheduled`, `next_attempt_at`, `deadLetter` / `permanent_failure`.
6. **Idempotency:** Unique tenant keys; lease fencing; provider_reference for future providers.
7. **Ordering:** Best effort; no global order.
8. **Events:** Publish after durable commit; not SoR.
9. **Realtime:** SSE attention only; outside claim transaction.
10. **Redis/broker:** Not required for correctness.
11. **Providers / SMTP / Email SoR:** Out of scope (ADR-0074 conditional later).

## Rationale

Highest decision-matrix score; realises ADR-0071 persistence already decided; reuses 0065; shared-host portable; simplest durable multi-instance model without new infrastructure.

## Consequences

### Positive

Durable restart recovery · safe multi-worker · admin visibility · ADR-0071 alignment · foundation for future provider adapters.

### Negative

DB load for claiming · ENG effort to replace Maps · cutover complexity from Phase A memory.

## Rejected alternatives

B (optional later wake-up only) · C (events≠queue) · D (unnecessary broker) · E (fails MUST).

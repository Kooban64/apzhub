## Executive summary

The Event & Notification Framework delivers two **separate platform concepts** in one coordinated package:

1. **Event Framework** — declare, register, publish, and dispatch platform events through an in-process Event Bus
2. **Notification Framework** — map events to user-facing notifications and deliver them through Notification Experiences

Events and notifications are **never conflated**. Notifications consume events; events are never generated by notification code.

### Canonical execution pipeline

```text
Platform Capability
        ↓
Domain Event
        ↓
Event Bus
        ↓
Notification Mapping
        ↓
Notification Service
        ↓
Notification Presentation Layer
        ↓
Notification Experiences
```

See subsystem documents: [event-framework.md](./event-framework.md) · [notification-framework.md](./notification-framework.md).

## Event layer

### Event Registry

Server-authoritative index of declared platform events. Populated from:

- Platform event catalogue (`PLATFORM_EVENT_CATALOGUE`)
- Capability manifest `events` blocks (extraction scaffold)
- Built-in bootstrap in `bootstrapEventRegistry()`

Permission-filtered DTO (`EventRegistryDto`) hydrates diagnostics on the client. The client **does not publish** business events in SPR-006.

**Spec:** [SPR-006-ENF-event-registry.md](../specs/SPR-006-ENF-event-registry.md)

### Event Bus

`InProcessEventBus` validates envelopes against the Event Registry, dispatches to subscribers synchronously, and records publish diagnostics.

| Property       | SPR-006 behaviour                        |
| -------------- | ---------------------------------------- |
| Transport      | In-process only                          |
| Delivery       | Synchronous fan-out to subscribers       |
| Persistence    | None — session-scoped notifications only |
| Client publish | Not supported                            |

Primary production publisher today: **Action audit hook** → `capability.action.executed`.

**Spec:** [SPR-006-ENF-event-bus.md](../specs/SPR-006-ENF-event-bus.md)

### Domain events

Every dispatch uses **PlatformEventEnvelope** (`envelopeId`, `eventId`, `category`, `timestamp`, `payload`, …).

Four canonical categories: `system`, `user`, `capability`, `integration`.

## Notification layer

### Notification Registry

Index of **notification routes** — metadata describing how an event pattern maps to a notification kind and channel. Routes declare:

- `eventPattern` — e.g. `capability.action.executed`
- `notificationKind` — `inbox`, `toast`, `banner`, …
- `channel` — `in-app` (SPR-006), `email`, `sms`, … (stubs)
- Template refs for title/body rendering

**Spec:** [SPR-006-ENF-notification-registry.md](../specs/SPR-006-ENF-notification-registry.md)

### Notification Mapping

`DefaultNotificationMapper` subscribes to the Event Bus. For each envelope:

1. Resolve matching routes from Notification Registry
2. Render templates (`{{payload.actionId}}`, `{{event.timestamp}}`, …)
3. Produce immutable `NotificationItem` records
4. Hand off to Notification Service via `wireAppEventNotifications()` (production) or test helper (unit tests only)

Mapping **never publishes** events.

**Spec:** [SPR-006-ENF-notification-mapper.md](../specs/SPR-006-ENF-notification-mapper.md)

### Notification Service

Session-scoped store and public read/update API:

| Method                           | Purpose                                  |
| -------------------------------- | ---------------------------------------- |
| `listNotifications()`            | Active notifications for current session |
| `markRead(id)` / `markAllRead()` | Read state updates                       |
| `getUnreadCount()`               | Badge source                             |
| `subscribe(listener)`            | React re-render driver                   |
| `getDiagnostics()`               | Dev/health snapshots                     |

Hook: `useNotificationService()` inside `NotificationServiceProvider`.

**Spec:** [SPR-006-ENF-notification-service.md](../specs/SPR-006-ENF-notification-service.md)

### Notification Presentation Layer

Pure transforms from service read models to UI view models:

- `mapNotificationItemToViewModel()` — severity, read state, `actionRef`
- `formatNotificationRelativeTimestamp()` — **Just now**, **5m ago**, …
- `groupNotificationsByPriority()` — panel section headers

Hook: `useNotificationPresentation()` — mandatory for Experiences.

**Spec:** [SPR-006-ENF-notification-presentation-layer.md](../specs/SPR-006-ENF-notification-presentation-layer.md)

### Notification Experiences

Shell UI in `@apzhub/workspace`:

| Experience                    | Role                                    |
| ----------------------------- | --------------------------------------- |
| `NotificationBadgeExperience` | Unread count; opens panel               |
| `NotificationPanelExperience` | Grouped list; mark read / mark all read |

Mounted from `DesktopShell` when `enableNotificationBadge` / `enableNotificationPanel` are set.

**Spec:** [SPR-006-ENF-notification-experiences.md](../specs/SPR-006-ENF-notification-experiences.md)

## Application integration (`apps/web`)

Production wiring (EN-015, verified EN-016):

```text
Runtime.bootstrap()
  → loadSharedEventNotificationContext()
  → createAppEventNotificationContext()
  → loadEventNotificationHydration() (layout DTOs)
  → ActionWorkbenchShellProvider
       NotificationRegistryProvider
       NotificationServiceProvider (shared instance)
       WorkbenchProvider + createActionAuditEventBusHook
       wireAppEventNotifications() subscriber
       DesktopShell notification Experiences
```

**Spec:** [SPR-006-ENF-application-integration.md](../specs/SPR-006-ENF-application-integration.md)

## Bootstrap sequence

```text
1. Server: bootstrapEventRegistry() + bootstrapNotificationRegistry()
2. Server: filterEventRegistryDto() + filterNotificationRegistryDto()
3. Server: createAppEventNotificationContext()
      — Event Bus, Mapper, Notification Service (single instance)
      — wireAppEventNotifications(eventBus, mapper, service)
4. Layout: pass DTOs + diagnostics to ActionWorkbenchShellProvider
5. Client: NotificationRegistryProvider + NotificationServiceProvider
6. Client: audit hook on ActionExecutor → publish on successful execute
7. Client: Experiences consume useNotificationPresentation()
```

Server and client each hold a context instance for their runtime — notification store is **client session-scoped** by design (TD-EN15-02).

## Taxonomy summary

### Event categories

| Category    | Value         | Example                               |
| ----------- | ------------- | ------------------------------------- |
| System      | `system`      | `system.platform.bootstrap.completed` |
| User        | `user`        | `user.session.started`                |
| Capability  | `capability`  | `capability.action.executed`          |
| Integration | `integration` | `integration.connector.sync.failed`   |

### Notification kinds (SPR-006)

| Kind                         | SPR-006                       | Channel             |
| ---------------------------- | ----------------------------- | ------------------- |
| Inbox                        | ✅ Foundation                 | `in-app`            |
| In-App / badge source        | ✅ Foundation                 | `in-app`            |
| Toast                        | Scaffold (route + panel list) | `in-app`            |
| Banner                       | Scaffold metadata             | `in-app`            |
| Email / SMS / Push / Webhook | Interface stubs               | respective channels |

**Delivery channels are orthogonal to event categories.**

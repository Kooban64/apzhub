> **Programme:** APZHUB-GOVERNANCE-001  
> **Date:** 2026-07-20

---

## Improvement loop

```text
Observe (ops KPIs · incidents · KL friction)
  → Decide (ORB / Risk / Product Council)
  → Authorise (Owner programme if engineering)
  → Deliver / Practice
  → Accept / Measure
```

## Sources of improvement

| Source                | Typical outcome                       |
| --------------------- | ------------------------------------- |
| Post-incident reviews | Runbooks, Problems, Changes           |
| Ops maturity M1→M2    | Role staffing, cadence                |
| Product KL tickets    | Roadmap candidates (not silent scope) |
| ARB findings          | ADR / training                        |
| Backup drill failures | Resilience Changes                    |

## Anti-patterns

- “Just fix it in Production” without Change
- Expanding STOP items under “improvement”
- Implementing dashboards/monitoring without Approval
- Treating AI chat recommendations as backlog authority

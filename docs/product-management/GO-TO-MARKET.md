# APZHUB Go-To-Market Framework

> **Programme:** APZHUB-PRODUCT-MANAGEMENT-001  
> **Classification:** DOCUMENTATION ONLY  
> **Date:** 2026-07-19

---

## Purpose

Define how APZHUB products are positioned and introduced to markets. Not a campaign calendar or ad spend plan.

---

## Positioning pillars

1. **Enterprise Operating Platform** — one Workbench, many products — never “portal” or “launcher”.
2. **Self-hosted first** — customer control of data and engines (CE OSS).
3. **Brand-masked integrations** — users see Projects / Time / Support, not Plane / Kimai / Zammad.
4. **Law as flagship vertical** — primary commercial offering; suite as productivity spine.
5. **Honest maturity** — Production SemVer only where accepted; Concept products not sold as GA.

---

## Readiness gates before GTM claims

| Claim                      | Gate                                                       |
| -------------------------- | ---------------------------------------------------------- |
| “Production” product       | Owner-accepted SemVer or documented platform PRWL baseline |
| “Enterprise ready”         | Enterprise edition row + Identity/Admin/Observe posture    |
| “Analytics included”       | Analytics exits Concept; Metabase (or native) certified    |
| “Fully automated Workflow” | Execute path Owner-approved (today: read-only)             |

---

## Messaging do / don’t

| Do                            | Don’t                                                    |
| ----------------------------- | -------------------------------------------------------- |
| APZ product names             | Engine brand in customer UI copy                         |
| Document limitations          | Imply Enterprise Edition features without matrix         |
| Self-hosted CE story          | Mandate cloud-only                                       |
| Three-pillar governance story | Promise unimplemented dashboards / Event Bus automations |

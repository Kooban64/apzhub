# APZHUB Roadmap Management

> **Programme:** APZHUB-PRODUCT-MANAGEMENT-001  
> **Classification:** DOCUMENTATION ONLY  
> **Commercial view:** [COMMERCIAL-ROADMAP.md](./COMMERCIAL-ROADMAP.md)  
> **Date:** 2026-07-19

---

## Purpose

Standard process for building and communicating APZHUB product roadmaps. Aligns commercial stages with engineering evidence.

---

## Roadmap lifecycle (standard)

| Stage                 | Commercial meaning              | Typical artefacts                 |
| --------------------- | ------------------------------- | --------------------------------- |
| **Concept**           | Problem / opportunity           | Vision notes                      |
| **Planning**          | Scope, personas, edition intent | Definition pack · commercial card |
| **Implementation**    | Approved delivery               | Sprint / programme docs           |
| **Beta**              | Limited exposure                | Feedback · limitations            |
| **Release Candidate** | Claim freeze                    | Release evidence pack             |
| **Production**        | Owner-accepted baseline         | SemVer register row               |
| **Maintenance**       | Sustain                         | Patch notes                       |
| **Retirement**        | Exit                            | EOL notice                        |

---

## Horizon model

| Horizon | Window (indicative)                 | Content                                         |
| ------- | ----------------------------------- | ----------------------------------------------- |
| Now     | Current Production baselines        | Projects 1.1.0 · Time 1.0.0 · Support 1.0.0     |
| Next    | Owner-gated Patch/Minor / packaging | Support 2.0 planning · Documents product SemVer |
| Later   | Strategic                           | Analytics · Workflow execute · Hosted SaaS      |
| Vision  | Multi-year                          | Full suite + Law primary vertical GTM           |

Indicative only — not a delivery commitment.

---

## Cadence

| Ritual                     | Owner           | Output                            |
| -------------------------- | --------------- | --------------------------------- |
| Monthly roadmap sync       | Product Owners  | Updated COMMERCIAL-ROADMAP themes |
| Quarterly portfolio review | Portfolio Owner | Edition / GTM adjustments         |
| Per release                | Release Owner   | SemVer + commercial release notes |

---

## Rules

1. Roadmaps do **not** invent programme IDs.
2. Roadmaps do **not** authorise implementation.
3. Public roadmap claims must match certified / accepted evidence.
4. Engineering portfolio order remains advisory ([APZHUB-PRODUCT-PORTFOLIO §5](../products/APZHUB-PRODUCT-PORTFOLIO.md)).

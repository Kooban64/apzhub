## Principle

> **Documents exist to support work. Work does not exist to organise documents.**

## Mental model

Do not ask: “Can the user manage documents?”  
Ask: **“Can the user manage work that happens to involve documents?”**

Wrong shape:

```text
Repository → Upload → Browse
```

Right shape:

```text
Project / Support / Evidence / Contract / Time / Quality
        → Attach Document
        → Document appears
        → Document lifecycle continues
```

## Work Context Principle

Every document should naturally answer:

- What work is this supporting?
- Who owns the work?
- Why is this document here?
- What decision depends on it?
- What happens next?

If those cannot be answered from document context, the experience is incomplete.

## Product protection

APZ Documents remains a **product**. It must not disappear.

Its responsibility:

> Protect, organise and govern enterprise documents.

It should not feel like the centre of the user’s world. The best compliment:

> “I didn’t even realise I was using the document system.”

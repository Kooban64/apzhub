## Strategic objective

Determine whether APZ Workflow delivers a native APZHUB experience that models, governs and visualises **business processes** — while keeping automation/execution invisible and preserving SoR boundaries with the four Reference Implementations.

Identify gaps only. Do not implement solutions.

## Audit areas (mandatory)

1. Native Experience
2. Engine Leakage
3. Intent vs Execution conflation
4. Workflow Test (business language)
5. System of Record Boundaries
6. Relationship to RI #001–#004
7. Enterprise Capability Alignment

## Central questions

> When a user thinks about a process, do they start with a **business journey** — or with runs, schedules, providers, and engines?

> Can every user-visible workflow be described without mentioning software?

Expected long-term answer: **business journey first**; engines never first-class.

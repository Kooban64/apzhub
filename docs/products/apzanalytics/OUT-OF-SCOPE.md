APZ Analytics will **not** become these products. Strong boundaries protect SoR discipline and insight identity.

| Not APZ Analytics                                                      | Belongs to                                   |
| ---------------------------------------------------------------------- | -------------------------------------------- |
| System of Record for projects / tickets / time / documents / processes | RI products #001–#005                        |
| Operational work execution                                             | Projects, Support, Time, Documents, Workflow |
| Quality engineering platform                                           | APZQEP                                       |
| BI engine / warehouse brand as product                                 | Invisible implementation                     |
| Chart / widget / dashboard catalogue as identity                       | Presentation only (after questions)          |
| Legal practice product                                                 | APZ Law Platform                             |
| Workflow orchestration product                                         | APZ Workflow                                 |
| Unified search / notifications redesign                                | Lane 1 platform evolution (evidence-driven)  |
| Identity / authentication product                                      | APZHUB platform identity                     |

## Boundary rules

1. Analytics **explains**; it does not become the business.
2. Analytics **consumes** SoRs; it never becomes one.
3. **Questions before visualisations** — “add a chart” is not a scope driver.
4. Lane 1 platform evolution remains evidence-driven — not justified by opening Analytics.

## Principle

A document should **almost never exist in isolation**. It should answer:

| Question                             | Intent                                   |
| ------------------------------------ | ---------------------------------------- |
| What is this document?               | Identity / type                          |
| Why does it exist?                   | Purpose                                  |
| Which work item is it related to?    | Delivery / task context                  |
| Which project?                       | APZ Projects reference                   |
| Which support request?               | APZ Support reference                    |
| Which quality evidence?              | APZQEP reference                         |
| Which customer or organisation?      | Business context (when applicable)       |
| What is its current lifecycle state? | Capture → active → superseded / retained |

## Work-first alignment

> The document service supports the work; it does not become the work.

Users think: “I’m attaching a document to my project,” “I’m reviewing evidence,” “I’m signing a contract” — not “I’m uploading to [engine].”

This principle guides N-01…N-03 experience decisions. It does not authorise platform Search / Notifications / My Work changes (Lane 1).

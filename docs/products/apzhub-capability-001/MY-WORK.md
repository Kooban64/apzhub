## Purpose

Define the single APZHUB work queue.

> Users open **My Work** to see what needs them — not which product to launch.

My Work is a **platform experience**. Products may contribute items; they do not own the queue.

## Primary queues

| Queue                  | Meaning                                             |
| ---------------------- | --------------------------------------------------- |
| **Assigned to me**     | I am the actor responsible for the next step        |
| **Waiting for me**     | Progress is blocked until I act                     |
| **Needs my attention** | Something important changed that requires awareness |
| **Blocked**            | I cannot proceed until something else unblocks it   |
| **Due today**          | Commitment or SLA lands within the current day      |
| **High priority**      | Elevated urgency relative to my other work          |
| **Needs approval**     | I am the approver                                   |
| **Ready to release**   | Quality / release readiness awaits my gate action   |
| **Waiting for others** | I am waiting on someone else                        |
| **Recently completed** | Work I finished — for continuity and follow-up      |

## Queue rules

1. Items are **work items**, not product tabs.
2. Originating product is secondary metadata — never the primary label.
3. Permissions still apply; My Work never reveals unauthorised items.
4. Empty queues are valid and should feel calm, not broken.
5. “Recently completed” is finite and personal — not an organisation-wide archive.

## What My Work is not

| Not My Work            | Reason                                           |
| ---------------------- | ------------------------------------------------ |
| A product home page    | Homes remain product-owned                       |
| A global search result | Search discovers; My Work obligates              |
| A notification dump    | Attention may feed My Work; it is not My Work    |
| A dashboard of metrics | Metrics are Horizon 3 later; not this definition |

## Relationship to “My …” surfaces

| Surface            | Role relative to My Work                     |
| ------------------ | -------------------------------------------- |
| My Work            | Canonical obligation queue                   |
| Needs My Attention | Subset / lens of My Work + attention signals |
| Approvals          | Lens: Needs approval                         |
| Waiting for Others | Lens: Waiting for others                     |
| Due Today          | Lens: Due today                              |
| Recently Completed | Lens: Recently completed                     |

Specialised “My …” product lenses (e.g. my tickets, my time records) may exist later as **filtered views into the same work model** — not competing queues.

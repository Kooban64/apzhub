# Knowledge Consumers — Who Uses Organisational Memory

| Field     | Value                             |
| --------- | --------------------------------- |
| Programme | APZHUB-KNOWLEDGE-ARCHITECTURE-001 |
| Status    | **COMPLETE**                      |
| Timestamp | 20260806T063000Z                  |

## Rule

Everything else **consumes** organisational memory.  
Knowledge does not become those consumers.

```text
Organisational Memory (Knowledge)
        →
Consumed by people, products, and future capabilities
```

---

## Human consumers

| Consumer                    | Need from memory                                      |
| --------------------------- | ----------------------------------------------------- |
| **Individual contributors** | What should I do / follow in this situation?          |
| **Managers**                | What guidance applies to my team’s work?              |
| **Executives**              | What institutional understanding underpins decisions? |
| **Approvers / curators**    | What is pending review; what is outdated?             |
| **New joiners**             | How does APZOR do this? (onboarding understanding)    |

---

## Product consumers (by reference)

| Product           | Consumes memory for                                               |
| ----------------- | ----------------------------------------------------------------- |
| **APZ Projects**  | Delivery playbooks; lessons from prior work                       |
| **APZ Support**   | Runbooks; solved-before understanding                             |
| **APZ Documents** | “How this document type is used” — not file ownership             |
| **APZ Workflow**  | Why this stage / procedure exists                                 |
| **APZ Analytics** | Prior decision rationale as context for questions                 |
| **APZ Law**       | Operational explanation of obligations (Law still owns artefacts) |
| **APZ Time**      | How effort should be classified / recorded                        |
| **APZQEP**        | Engineering / quality practice guidance                           |
| **Shell / Help**  | Product-adjacent understanding (not a second Help SoR)            |

Products show memory **in context**. They do not absorb Knowledge’s SoR.

---

## Platform / future consumers

| Consumer                                         | Role                                                       |
| ------------------------------------------------ | ---------------------------------------------------------- |
| **Platform search (knowledge scope)**            | Find memory objects — not replace all-entity search        |
| **Future AI assistants**                         | Retrieve approved memory — consumer only                   |
| **Future domain products** (People, Customer, …) | Consume memory the same way Core products do               |
| **Notifications / attention** (if ever wired)    | Point people to relevant memory — delivery owned elsewhere |

---

## Consumer rights and limits

| Consumers may                    | Consumers must not                          |
| -------------------------------- | ------------------------------------------- |
| Display approved memory          | Silently edit organisational memory         |
| Filter by permission and context | Bypass Knowledge approval                   |
| Deep-link to referenced SoRs     | Treat memory as operational SoR             |
| Suggest “related memory”         | Force AI generation as authoritative memory |

---

## Primary UX principle

The most important consumption mode is **in context**, not “open Knowledge and hunt.”

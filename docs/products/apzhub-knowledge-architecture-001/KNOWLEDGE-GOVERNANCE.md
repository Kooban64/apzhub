## Identity reminder

Knowledge owns **Enterprise Organisational Memory** only.  
Governance here is governance of **understanding**, not of operational records.

---

## Ownership

| Question                                    | Answer                                                                |
| ------------------------------------------- | --------------------------------------------------------------------- |
| Who owns organisational memory as a domain? | **Product Board / Owner** for strategy; domain steward for day-to-day |
| Who owns a specific memory object?          | **Accountable author + Approver** (named)                             |
| Who owns referenced SoR content?            | **The SoR product** (Documents, Law, Projects, …) — unchanged         |
| Who owns platform permissions?              | **APZHUB Platform**                                                   |

---

## Roles

| Role                        | Responsibility                                              |
| --------------------------- | ----------------------------------------------------------- |
| **Domain Owner** (business) | Scope of organisational memory; escalate identity conflicts |
| **Knowledge Steward**       | Taxonomy, quality of curation, review cadence               |
| **Curator / Author**        | Draft and maintain memory objects                           |
| **Approver**                | Approve publish / retire for a scope                        |
| **SoR Liaison**             | Ensure references to Documents / Law / etc. stay accurate   |
| **Consumer products**       | Display memory; never redefine it                           |
| **Product Board**           | Domain investment; resolve cross-domain identity disputes   |

---

## Approval

| Decision                                | Who                                                              |
| --------------------------------------- | ---------------------------------------------------------------- |
| Publish new memory                      | Approver for that collection / domain scope                      |
| Material change to published memory     | Approver (re-approval)                                           |
| Retire / supersede                      | Approver + Steward awareness                                     |
| Memory that interprets Law / policy     | Approver **plus** Law liaison when scope is governance-sensitive |
| Memory that claims quality practice     | Approver **plus** APZQEP liaison when scope is quality-sensitive |
| Cross-product “standard way of working” | Steward; escalate to Domain Owner / Board if contested           |

Approval ≠ legal advice. Approval ≠ changing Law SoR.

---

## Retirement

| Who may retire       | Condition                                        |
| -------------------- | ------------------------------------------------ |
| Approver             | Scope they control                               |
| Steward              | Hygiene / failed review (with notice)            |
| SoR Owner (request)  | Referenced artefact withdrawn — Steward must act |
| Domain Owner / Board | Strategic withdraw                               |

Retired memory is not current guidance. Retention of historical understanding for audit of _what we believed_ may exist; it must be labelled non-current.

---

## Conflict resolution

| Conflict                                            | Resolution                                                   |
| --------------------------------------------------- | ------------------------------------------------------------ |
| Memory contradicts Documents / Law / Projects truth | **SoR wins**; memory revised or retired                      |
| Two memories conflict                               | Steward mediates; Approvers decide; escalate to Domain Owner |
| Product wants to own “help” vs Knowledge            | Board: product Help vs organisational memory boundary        |
| Pressure to become wiki / AI / search product       | Reject — identity is organisational memory only              |

---

## Quality linkage

APZQEP governs **changes to the Knowledge product** (when it exists), not the content of every memory object.  
Content governance is this document.  
Product engineering quality is APZQEP.

1. A confirmed production defect.

## Defect policy

If an issue is reported:

1. Confirm whether it is a genuine defect.
2. Classify as: Defect · Training · Documentation · Operational Process · Product Enhancement · Portfolio Capability.
3. Only confirmed defects may proceed to engineering (and only with Owner Auth under APZQEP).
4. Everything else waits for Product Board review.

## Product Board trigger thresholds

Notify the Owner immediately only when a threshold is met:

| Threshold           | Meaning                                                                      |
| ------------------- | ---------------------------------------------------------------------------- |
| **A — Critical**    | Production defect preventing normal operation                                |
| **B — Operational** | Same measurable friction observed repeatedly across pilot users              |
| **C — Strategic**   | Evidence that a new portfolio capability would significantly reduce friction |

If none are met: **Continue observing.**

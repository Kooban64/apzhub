# Product Enablement Checklist

| Field     | Value              |
| --------- | ------------------ |
| Programme | APZHUB-OPERATE-001 |
| Status    | **IN FORCE**       |

Use when enabling an adopted product for a department or cohort. Repeat per product.

## Common (every product)

- [ ] Department / cohort named
- [ ] Role map reviewed ([ROLE-ENABLEMENT.md](./ROLE-ENABLEMENT.md))
- [ ] Permissions granted (least privilege)
- [ ] Users completed Day-0 onboarding
- [ ] Support path known
- [ ] Success criterion: users can complete a real task without engine training

## APZ Projects

- [ ] Cohort has delivery work in Projects
- [ ] Project Managers / Developers can open assigned work from My Work or Projects
- [ ] Product-local My Work retained; portfolio My Work aggregates
- [ ] Ops pack referenced: `docs/products/apzprojects/`

## APZ Support

- [ ] Cohort handles or raises service work
- [ ] Agents / requesters can open assigned / relevant requests
- [ ] Escalation path to Support product, not engine console
- [ ] Ops pack referenced: `docs/products/apzsupport/` (or Support native ops)

## APZ Time

- [ ] Cohort expected to capture effort
- [ ] Users can start / stop / submit time in APZ Time
- [ ] “Submit today’s timesheet” understood via My Work when surfaced
- [ ] Ops pack referenced: Time RI / native ops faces

## APZQEP (engineering cohort only)

- [ ] Engineers know Quality Flow is mandatory for product change
- [ ] Checklists located (product ops packs)
- [ ] No APZQEP redesign as part of enablement

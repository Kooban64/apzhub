## Principle

Metrics measure **business outcomes**, not engine performance, retrieval latency, or model accuracy.

## Mission-level metric themes

| Metric theme                      | Business question                                                     |
| --------------------------------- | --------------------------------------------------------------------- |
| Time to find trusted guidance     | How quickly can someone reach approved guidance for the work at hand? |
| Reuse of organisational knowledge | Is published memory actually reused across work, not only stored?     |
| Reduction in duplicated effort    | Are teams reinventing answers that already exist as approved memory?  |
| Adoption of approved practices    | Are standards and procedures applied where they apply?                |
| Knowledge freshness               | Is current memory current — reviewed, superseded, or retired on time? |
| Context effectiveness             | Was memory shown in work context used to act correctly?               |
| Derivation discipline             | Does published memory cite trusted sources / SoR references?          |
| SoR discipline                    | Are there incidents of Knowledge being treated as operational SoR?    |

## Explicit non-metrics (this Mission)

| Not a Mission success metric      | Why                                                |
| --------------------------------- | -------------------------------------------------- |
| Vector search recall / RAG scores | AI / RAG out of scope                              |
| Index size / crawl coverage       | Not a search product                               |
| Page views alone                  | Destination anti-pattern — prefer in-context use   |
| Engine uptime as product success  | Infrastructure, not organisational memory outcomes |

Detailed operational metrics belong in Native Adoption N-04 after Mission Approval.

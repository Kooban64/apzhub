## Competitor profiles

### Tuskr

| Dimension      | Assessment                                                        |
| -------------- | ----------------------------------------------------------------- |
| Vision         | Modern, affordable standalone test management for small/mid teams |
| Architecture   | Cloud SaaS TCMS; lightweight                                      |
| Capabilities   | Cases, suites, runs, Jira sync; simpler than TestRail             |
| AI             | Limited / marketing-variable; not AI-governance oriented          |
| Automation     | API/CI integrations typical of light TCMS                         |
| Reporting      | Basic–good for SMB                                                |
| Certification  | Not a continuous certification SoR                                |
| Integrations   | Jira-focused; narrower enterprise connector depth                 |
| DX             | Clean UX; low friction onboarding                                 |
| Enterprise     | Weak vs regulated evidence/cert needs                             |
| Commercial     | Budget-friendly; free tiers common in category                    |
| **Strengths**  | Price, simplicity, speed to value                                 |
| **Weaknesses** | Depth, governance, AI control, enterprise certification           |

**QEP implication:** Do not compete on cheapest SMB TCMS. Compete on enterprise QE + certification + governed AI.

### TestRail

| Dimension      | Assessment                                                             |
| -------------- | ---------------------------------------------------------------------- |
| Vision         | Market-leading standalone test case management                         |
| Architecture   | Standalone SaaS/app with optional Jira/ADO links                       |
| Capabilities   | Mature plans/cases/runs, milestones, reporting                         |
| AI             | Expanding (generation, prioritisation, NL search) — still TCMS-centric |
| Automation     | Strong API/CI import patterns                                          |
| Reporting      | Benchmark for classic QA reporting                                     |
| Certification  | Release/milestone tracking; not continuous certification platform      |
| Integrations   | Broad ALM/CI; not platform-suite native                                |
| DX             | Familiar to QA orgs; less IDE/agent native                             |
| Enterprise     | Strong commercial enterprise tiers                                     |
| Commercial     | Per-user SaaS; established brand                                       |
| **Strengths**  | Maturity, brand, reporting, standalone independence from Jira          |
| **Weaknesses** | Still “test management” identity; AI bolted on; weak MCP/IDE SoR story |

**QEP implication:** Match commodity TCMS expectations; win on QE identity, certification SoR, platform-first, MCP-native agents.

### JUnit / Playwright / Cypress ecosystems

| Ecosystem      | Role vs QEP                                                                   |
| -------------- | ----------------------------------------------------------------------------- |
| **JUnit**      | Unit/integration runner ecosystem — QEP records/links, does not replace       |
| **Playwright** | E2E runner/framework — QEP ingests results/evidence; never becomes Playwright |
| **Cypress**    | E2E runner — same boundary                                                    |

**Shared weakness of runner ecosystems alone:** No enterprise certification SoR, weak requirement traceability, no governed AI quality agents, fragmented evidence.

## Cross-competitor synthesis

| Theme         | Market pattern                                       | QEP stance                                 |
| ------------- | ---------------------------------------------------- | ------------------------------------------ |
| Identity      | Most products are TCMS or ALM plugins                | **Quality Engineering Platform**           |
| AI            | Generation/prioritisation race; weak audit/SoR rules | AI-native **with** human gates & never-SoR |
| Architecture  | Jira-locked vs standalone SaaS                       | **Platform-first APZHUB** native SoR       |
| Certification | Milestone reports; rare continuous certification     | **Core differentiator**                    |
| IDE/agents    | Emerging; governance immature                        | **MCP-native governed SoR**                |
| Runners       | Separate from management                             | Orchestrate/ingest only                    |

## Competitive opportunity map

| Opportunity                               | Why open                                          |
| ----------------------------------------- | ------------------------------------------------- |
| Continuous certification SoR              | Underserved as first-class product                |
| Evidence-first + immutable audit          | Commodity TCMS weak                               |
| MCP/IDE governed quality                  | Market talking AI; few own quality SoR for agents |
| Suite adjacency (Projects/Docs/Analytics) | Standalone TCMS cannot match                      |
| Verification maturity model               | Rare as productised journey                       |
| Self-hosted enterprise without Kiwi       | Differentiates from SaaS-only leaders             |

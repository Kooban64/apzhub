# APZ QEP — Customer Expectations

> **Programme:** APZQEP-DISCOVERY-001  
> **Focus:** What enterprise customers now expect from a Quality Engineering Platform

## Expectation tiers

### 1. Commodity capabilities (table stakes)

Must exist or buyers discard the product early:

| Expectation                     | Notes                          |
| ------------------------------- | ------------------------------ |
| Projects / spaces               | Organise quality work          |
| Plans, suites, cases/procedures | Structured verification assets |
| Manual execution & results      | Pass/fail/blocked/skip         |
| Basic defect linkage            | To cases/runs                  |
| Search & filters                | Find assets quickly            |
| REST API                        | Automation & integration       |
| CI result import                | Link pipelines                 |
| Role-based access               | Basic RBAC                     |
| Standard reports                | Coverage, pass rate            |
| Jira or ALM sync (optional)     | Expected even if not SoR       |

### 2. Competitive capabilities (parity with leaders)

Needed to shortlist against TestRail / Xray / Qase class:

| Expectation                      | Notes                    |
| -------------------------------- | ------------------------ |
| Requirements ↔ test traceability | Matrices and gap views   |
| Automation identifiers on cases  | Hybrid manual/auto       |
| Dashboards for QA leads          | Operational quality      |
| Versioning of cases/plans        | Change control           |
| Webhooks                         | Event-driven integration |
| Good UX / performance            | Modern expectations      |
| Export for audits                | CSV/PDF packs            |
| Milestone / release association  | Release context          |

### 3. Enterprise capabilities (win enterprise deals)

| Expectation                           | Notes                    |
| ------------------------------------- | ------------------------ |
| SSO / central IAM                     | No product login silo    |
| Tenant isolation                      | Multi-customer readiness |
| Immutable audit of privileged actions | Who certified what       |
| Evidence retention policies           | Compliance               |
| Configurable quality gates            | Release readiness        |
| Multi-role certification sign-off     | Human accountability     |
| Self-hosted / data residency options  | Enterprise procurement   |
| Observability & health                | Ops trust                |
| Brand-safe UX (no engine chrome)      | Professional product     |
| Honest known limitations              | Supportability           |

### 4. Emerging AI capabilities (2025–2026 wave)

| Expectation                        | Caution                 |
| ---------------------------------- | ----------------------- |
| AI test/verification generation    | Must not silent-commit  |
| AI prioritisation / coverage hints | Explainability expected |
| NL search / ask quality questions  | Permission-filtered     |
| IDE/agent assistance               | Governance required     |
| Flaky / failure clustering         | Assistive only          |

Enterprise buyers increasingly ask: _Who approved this? Can we audit the AI? Can we turn it off?_

### 5. Future market expectations (next 3–5 years)

| Expectation                                        | Implication for QEP       |
| -------------------------------------------------- | ------------------------- |
| Continuous certification                           | Core strategy             |
| Agent-native quality workflows (MCP)               | First-class               |
| Multi-provider AI with policy                      | Interchangeable providers |
| Knowledge-driven AI grounded in org playbooks      | Quality KB                |
| Executive quality intelligence                     | Not only QA dashboards    |
| Open ecosystem / marketplace of templates & agents | Later commercial          |
| Shift-right signals into SoR                       | Continuous verification   |

## Expectation vs QEP category choice

| If we only ship…                | Buyer perceives…               |
| ------------------------------- | ------------------------------ |
| Commodity TCMS                  | “Another TestRail” — price war |
| Competitive parity only         | Shortlist, no win theme        |
| Enterprise + cert + governed AI | Distinct category leader path  |

## Definition guidance

Definition **must** deliver commodity + competitive baselines for MVP credibility, while **protecting roadmap space** for enterprise differentiators and emerging AI/MCP — without enabling auto-certify.

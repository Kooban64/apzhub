# APZ QEP — Market Analysis

> **Programme:** APZQEP-DISCOVERY-001

## Market definition

| Layer          | Definition                                                                       |
| -------------- | -------------------------------------------------------------------------------- |
| Core           | Test case / test management software                                             |
| Expanding      | Quality Engineering platforms (requirements → verification → evidence → release) |
| Adjacent       | CI analytics, device clouds, ALM plugins, AI coding assistants                   |
| Target for QEP | Expanding layer — **Enterprise Quality Engineering Platform**                    |

## Market forces (2025–2026)

1. **AI coding assistants** generate tests faster than organisations can govern them.
2. **ALM gravity** (Jira/ADO/GitLab) pulls test management into plugins — fragmenting multi-tool enterprises.
3. **Automation density** rises; manual TCMS alone is insufficient.
4. **Compliance pressure** (audit, retention, evidence) rises in regulated and enterprise buyers.
5. **Platform engineering** expects shared identity, observability, and self-hosted options.
6. **MCP / agent protocols** create a new integration surface — and a new governance gap.

## Competitive structure

```text
Commodity TCMS features  ←  crowded (TestRail/Qase/Tuskr/…)
ALM-embedded testing     ←  strong moat for Jira/ADO/GitLab vendors
Automation analytics     ←  Allure/GitLab/device clouds
Governed AI + Cert SoR   ←  UNDER-SERVED  ← QEP primary attack surface
```

## Strategic conclusion

The winning long-term category is **not** “better TestRail.” It is **Enterprise Quality Engineering with certification, evidence, and governed AI on a platform**. Definition must protect that category choice.

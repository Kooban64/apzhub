# APZ QEP — Permanent Product Principles

> **Programme:** APZQEP-DISCOVERY-001  
> **Status:** **ACCEPTED** with Discovery · elevated into [../constitution/PRODUCT-CONSTITUTION.md](../constitution/PRODUCT-CONSTITUTION.md)

## Principles

1. **Quality before testing** — Testing is a means; quality outcomes are the product purpose.
2. **Verification before execution** — Design what “good” means before running activity.
3. **Evidence before opinion** — Claims require artefacts and references in SoR.
4. **Certification before release** — Human-approved certification state precedes release confidence.
5. **AI assists humans** — AI drafts, analyses, and recommends.
6. **Humans remain accountable** — No silent SoR authority for machines; never auto-certify.
7. **Knowledge is reusable** — Playbooks, templates, and libraries compound organisational learning.
8. **Everything is traceable** — Requirements ↔ verifications ↔ defects ↔ evidence ↔ releases.
9. **Everything is auditable** — Privileged and certification actions leave immutable history.
10. **Everything is measurable** — Coverage, risk, readiness, and quality trends are first-class.
11. **Platform before product silo** — Module → Platform Service → Connector → Engine only.
12. **QEP is the System of Record** — External tools and AI never replace QEP authority.
13. **Progressive maturity** — Support organisations from manual to continuous certification.
14. **Self-hosted first** — Enterprise control of data and deployment is a default preference.
15. **Honest limitations** — Never oversell; publish known limitations per release.

## Anti-principles (explicitly rejected)

| Anti-principle                      | Reason                          |
| ----------------------------------- | ------------------------------- |
| Feature parity with every TCMS      | Leads to undifferentiated clone |
| AI as SoR                           | Compliance and safety failure   |
| Engine brands in UX                 | Breaks product identity         |
| Module→engine shortcuts             | Architectural defect            |
| Certification as a PDF afterthought | Misses category opportunity     |

## Governance

Once Owner-accepted, these principles are cited by Definition, Architecture, and Engineering programmes. Changes require Owner Decision.

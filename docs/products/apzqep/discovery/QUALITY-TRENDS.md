# APZ QEP — Quality Engineering Trends

> **Programme:** APZQEP-DISCOVERY-001

| Trend                        | What it means                            | QEP response                                                    |
| ---------------------------- | ---------------------------------------- | --------------------------------------------------------------- |
| **Shift-left testing**       | Verify earlier in design/dev             | Requirements + IDE/MCP draft verification; still human-accepted |
| **Shift-right validation**   | Learn from prod/ops signals              | Continuous verification ingest (later phases)                   |
| **Continuous verification**  | Ongoing signals, not only release cycles | Run types + dashboards; maturity L5                             |
| **Continuous certification** | Cert state maintained as change happens  | Flagship differentiator; human re-approval                      |
| **Quality engineering**      | Broader than test execution              | Product identity (not TCMS)                                     |
| **Risk-based testing**       | Prioritise by risk/impact                | Risk entity + AI risk assist                                    |
| **Developer experience**     | Quality tools must fit IDE/CI            | MCP + CI metadata; no runner replacement                        |
| **Platform engineering**     | Shared platforms, golden paths           | Native APZHUB Platform Services                                 |
| **AI-assisted engineering**  | AI writes code/tests                     | Governed AI; never SoR; never auto-certify                      |
| **Release intelligence**     | Go/no-go from multi-signal fusion        | Release readiness + executive dashboards                        |

## Trend implications (priority for Definition)

1. Speak **Quality Engineering**, not “test cases.”
2. Make **certification & evidence** as visible as execution.
3. Treat **IDE/agent** as a first-class client class.
4. Plan **continuous** modes without abandoning structured manual verification.
5. Keep **platform engineering** alignment (identity, audit, observability).

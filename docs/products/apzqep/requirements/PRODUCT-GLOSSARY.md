# APZ QEP — Product Glossary

> **Programme:** APZQEP-REQ-001

| Term                                | Definition                                                                                           |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------- |
| **APZ QEP**                         | APZ Quality Engineering Platform — official product name                                             |
| **APZ TCMS**                        | Former product name (Test Case Management System) — historical                                       |
| **Quality Engineering**             | Discipline of governing quality across the SDLC; broader than test management                        |
| **Verification**                    | Work unit proving a requirement or risk is addressed (manual, automated, AI-assisted, or continuous) |
| **Verification procedure**          | Reusable specification of how to verify (includes classical test cases)                              |
| **Verification plan**               | Scoped plan for verification activities against a release or objective                               |
| **Verification suite**              | Organised collection of verification procedures                                                      |
| **Verification run / execution**    | Instance of executing verification with results                                                      |
| **Requirement (quality)**           | Approved need or constraint that verification must address                                           |
| **Traceability**                    | Links among requirements, verifications, defects, evidence, and releases                             |
| **Evidence**                        | Artefacts or references proving verification outcomes (screenshots, logs, reports)                   |
| **Certification**                   | Human-approved quality state for a release/scope with audited sign-off                               |
| **Continuous Certification**        | Ongoing maintenance of certification state as changes occur                                          |
| **Release readiness**               | Aggregated go/no-go signal from gates, coverage, defects, evidence                                   |
| **System of Record (SoR)**          | Authoritative store — for quality data, **APZ QEP**                                                  |
| **AI assistant**                    | Model/agent that drafts or suggests; never authoritative SoR                                         |
| **AI Quality Agent**                | Governed agent performing QE assistant tasks via authorised tools (e.g. MCP)                         |
| **MCP**                             | Model Context Protocol — preferred governed IDE/agent integration model                              |
| **Maturity level**                  | Organisation’s progressive QE capability stage (see MATURITY-MODEL)                                  |
| **Platform Service**                | APZHUB business service layer; modules call services, not connectors                                 |
| **Connector / Integration Adapter** | Integration SDK adapter to external engines/providers                                                |
| **Brand masking**                   | User-facing names never expose backend engine brands                                                 |

## Lessons

1. **Provider-neutral first pays off** — Playwright as a provider, not product identity, keeps Wave 2+ additive.
2. **Platform package placement matters** — `@apzhub/platform-automation` is reusable beyond APZQEP.
3. **Readiness gate before integrations** — APZQEP-161R prevented stacking Wave 2 on unvalidated UX/ops assumptions.
4. **Differentiator is orchestration** — evidence, lifecycle, certification, and governance matter more than tool count.
5. **Residuals must be classified, not ignored** — media theatre and durable store are real, but not Wave 1 blockers.
6. **Hands-on use remains essential** — Board certification does not replace Owner/operator practice on a live host.

## Carry into Wave 2

- Keep CI integrations calling the Automation Engine, never Playwright APIs.
- Do not let GitHub branding replace APZQEP product language.
- Prefer durable execution history early if ops feedback demands it — as a scoped programme, not silent scope creep.

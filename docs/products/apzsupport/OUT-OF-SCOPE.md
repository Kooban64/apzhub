APZ Support will **not** become these products. Strong boundaries protect focus and portfolio clarity.

| Not APZ Support                            | Belongs to                                                             |
| ------------------------------------------ | ---------------------------------------------------------------------- |
| Project / work delivery management         | APZ Projects                                                           |
| Time tracking and utilisation              | APZ Time                                                               |
| Document / records management              | APZ Documents                                                          |
| Workflow / automation product              | APZ Workflow                                                           |
| Analytics / BI product                     | APZ Analytics                                                          |
| Legal practice product                     | APZ Law Platform                                                       |
| CRM / sales pipeline                       | Outside this mission (unless separately authorised as another product) |
| Finance / billing product                  | Outside this mission                                                   |
| Identity provider / authentication product | APZHUB platform identity (not owned by APZ Support)                    |
| General-purpose collaboration suite        | Outside this mission                                                   |

## Boundary rules

1. Adjacent products integrate at the **APZHUB product** level when authorised — APZ Support does not absorb them.
2. “Helpful while we’re here” expansions that cross these boundaries require separate Owner Authorisation.
3. Out-of-scope does not mean “never useful later”; it means “not this product’s job.”

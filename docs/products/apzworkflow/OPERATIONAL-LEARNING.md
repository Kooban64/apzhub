## Rule

Every completed APZ Workflow release records Operational Learning.  
Friction is classified: Engineering · Operational · User · Training · Documentation · Product Enhancement · Portfolio Capability.

## Workflow-specific learning themes

- Did users start from business journeys or from operational/execution surfaces?
- Did execution vocabulary re-enter the standard UX?
- Did operator tools remain secondary?
- Was deferred automation capability mis-classified as a Workflow defect?
- Did Workflow stay above automation (intent vs execution)?

## Anti-patterns

- Skipping learning because “it was only docs”
- Opening Lane 1 or automation programmes from a single friction note
- Treating missing automation features as Native Adoption failure
- Collapsing Workflow into an automation console “for power users”

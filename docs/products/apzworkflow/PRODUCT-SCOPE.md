APZ Workflow **owns** the following business capabilities (product sense — not implementation):

| Capability                         | Meaning                                                                |
| ---------------------------------- | ---------------------------------------------------------------------- |
| Journey definition                 | Define the business steps that should occur across products            |
| Journey governance                 | Ownership, status, and rules for how journeys are maintained           |
| Step orchestration (intent)        | Express what should happen next and which product carries the work     |
| Cross-product references           | Link steps to Projects, Support, Time, Documents, quality by reference |
| Journey instance visibility        | See where a particular piece of work sits in a journey                 |
| Observability of journey progress  | Progress and completion signals for teams and leaders                  |
| Separation from execution runtimes | Keep automation engines as invisible implementation services           |

Scope is expressed as **what the product is responsible for**, not how it is built.

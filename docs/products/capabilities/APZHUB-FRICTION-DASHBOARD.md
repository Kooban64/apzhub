# APZHUB Friction Dashboard

| Field    | Value                                                              |
| -------- | ------------------------------------------------------------------ |
| Status   | **DEFINED** · observation instrument · **not scheduled for build** |
| Audience | Engineering (not management theatre)                               |
| Purpose  | Measure **friction**, not features                                 |

## Metrics

| Metric                                    | Why it matters                       |
| ----------------------------------------- | ------------------------------------ |
| Searches per session                      | Can users find things?               |
| Quick Actions used                        | Are people starting work faster?     |
| Notification open rate                    | Is the signal useful?                |
| Time from login → first productive action | Are we reducing friction?            |
| Product switches per task                 | Are users bouncing between products? |
| Failed searches                           | What's missing?                      |
| Most favourited actions                   | What should become easier?           |
| Unused capabilities                       | What are people ignoring?            |

## Rule

The dashboard informs the next capability. It does not invent a roadmap.

Implementation waits until Owner authorises instrumentation engineering. Until then: use the platform and record qualitative friction against these questions.

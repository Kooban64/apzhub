# Product Roadmap Standard (Definition Stage)

> **Programme:** APZHUB-PRODUCTS-003

## Purpose

Standardise how roadmaps appear in Definitions so Architecture and Owner decisions share a common shape.

## Mandatory roadmap sections

| Horizon                 | Content                             |
| ----------------------- | ----------------------------------- |
| Immediate deliverables  | MVP outcomes                        |
| Phase 2                 | Next value slice                    |
| Phase 3                 | Expansion                           |
| Long-term vision        | Directional only                    |
| Strategic opportunities | Optional bets — not authorised work |

## Rules

1. Roadmaps are **not** authorisations.
2. Every phase must respect Platform 1.4 Maintenance Mode.
3. Cross-product dependencies must name Platform Services, not peer modules.
4. Engine upgrades / provider swaps require ADR callouts in later Architecture.
5. Align with portfolio view in [../framework/PRODUCT-ROADMAP.md](../framework/PRODUCT-ROADMAP.md) without inventing programme IDs.

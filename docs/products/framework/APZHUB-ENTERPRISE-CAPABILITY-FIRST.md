## Principle

> **No new domain shall be authorised while an existing enterprise capability remains materially incomplete for its intended users.**

## Why

Identities of RI #001–#008 are complete.  
Capabilities are only beginning.

Architecturally mature products (Projects, Support, Analytics, Workflow, Knowledge, …) still have years of functional evolution ahead. Opening a new domain while those remain thin for daily users would dilute the portfolio.

## Tests before any new domain

| #   | Question                                                                                                     | Required answer                  |
| --- | ------------------------------------------------------------------------------------------------------------ | -------------------------------- |
| 1   | Does the Portfolio Baseline already contain this capability?                                                 | If yes → evolve existing product |
| 2   | Is any existing RI materially incomplete for intended users?                                                 | If yes → prefer its evolution    |
| 3   | Is there operational evidence of unmet need?                                                                 | Required                         |
| 4   | Would a new domain duplicate Work / Service / Time / Information / Process / Decision / Governance / Memory? | If yes → refuse                  |

# My Work Review — Standing Product Review

| Field     | Value                                                        |
| --------- | ------------------------------------------------------------ |
| Status    | **IN FORCE**                                                 |
| Timestamp | 20260805T105000Z                                             |
| Kind      | Standing product review                                      |
| Not       | Design meeting · Architecture review · Engineering programme |
| After     | Every meaningful period of My Work use                       |

## Purpose

Learn from real operational behaviour before expanding portfolio capability.

This is a **product review**. It does not authorise engineering by default.

## Cadence

Hold after every meaningful period of use (e.g. after a working week or sprint of production use — Owner / Product Board sets the rhythm).

Skip creating a programme. Produce short written answers to the five questions below.

## The five questions

Every My Work Review answers **only** these:

1. **What work did users complete successfully?**
2. **What work was difficult to complete?**
3. **What work never appeared in My Work but should have?**
4. **What unnecessary navigation still occurred?**
5. **What single improvement would reduce the most friction?**

That is the entire agenda.

## Decision rule

If none of the answers justify engineering, **nothing changes**.

Improvements that would invent a second SoR, move product ownership, or turn My Work into a second application are out of scope — escalate to Owner, do not “just build.”

## Companion questions (evidence lens)

Use alongside the governing investment question:

| Question                                 | Role                                |
| ---------------------------------------- | ----------------------------------- |
| **What did My Work fail to answer?**     | Primary — next investment candidate |
| **What caused a user to leave My Work?** | Companion — classify the leave      |

### Leave classification (critical)

| Leave reason                                                                                                      | Interpretation                                                            |
| ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| User needs a **missing portfolio capability** (e.g. cannot discover, was never notified, needs executive summary) | **Evidence** for a future Horizon 3 programme — only after pause criteria |
| User must use the **owning product** for detailed work                                                            | **Expected and healthy** — composition hands off; products answer “how”   |

That distinction keeps the composition layer from gradually becoming a second application.

## Success (not vanity)

| Not success                     | Success                                                                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Users opened My Work            | Users **stopped thinking about which product to open**                                                                         |
| Page views / click counts alone | Users start in My Work and complete work spanning Projects, Support, Time, APZQEP without consciously switching mental context |

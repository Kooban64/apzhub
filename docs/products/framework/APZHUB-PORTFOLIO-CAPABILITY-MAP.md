## Purpose

Describe APZHUB in terms of **enterprise business capabilities**, not software components or product engineering backlogs.

> This map is an executive planning view. It does not authorise features, architecture changes, or platform programmes.

## Rules

1. Organised around **business capabilities**, not modules or engines.
2. Products contribute to capabilities; engines remain invisible.
3. Does **not** replace mission, Native Adoption, or APZQEP discipline.
4. Does **not** authorise the next product programme by itself.
5. Update when a product reaches Reference Implementation or Owner Auth changes portfolio priority.

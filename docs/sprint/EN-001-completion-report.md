## Objective

Establish the Event & Notification Framework architecture — event taxonomy, notification taxonomy, ADRs, and technical specifications — before implementation begins. Documentation and architecture only; no production code.

---

## Architectural principle (locked)

```text
Platform Capability
        ↓
Domain Event
        ↓
Platform Event Bus
        ↓
Notification Mapping
        ↓
Notification Experience
```

Events and Notifications are **separate platform concepts**. Notifications consume events. Events are never generated by notifications.

## Key decisions locked in ADRs

| Decision                                                                        | ADR  |
| ------------------------------------------------------------------------------- | ---- |
| Unified `@apzhub/event-notification-framework`; retire event/notification stubs | 0030 |
| Separate `server/event/` and `server/notification/` modules                     | 0030 |
| EventRegistry + InProcessEventBus; server-only publish                          | 0031 |
| Four canonical event categories: system, user, capability, integration          | 0031 |
| Register-before-publish; standard PlatformEventEnvelope                         | 0031 |
| Eight notification kinds; five delivery channels                                | 0032 |
| EventToNotificationMapper subscribes to bus — never publishes                   | 0032 |
| SPR-006 scope: in-app channel; inbox + in-app kinds foundation                  | 0032 |
| Email/SMS/push/webhook — interface stubs only                                   | 0032 |
| Action audit → `capability.action.executed` first live event (EN-014)           | 0031 |
